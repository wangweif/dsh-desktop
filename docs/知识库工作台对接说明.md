# 知识库工作台对接说明

> 2026-10-12 落地。新增内置「知识库问答」工作台（`dsh-workbench-knowledge`），
> 桌面端**直连**农科小智统一知识库（RAGFlow），提供选库 + 流式问答（含参考
> 文档）。接口规范见飞书 wiki《农科小智知识库接口》（`SJOZwkIWAiewhsk1Wpbc1Hn4nUb`）。

## 功能与流程

```
面板（右侧业务区）                宿主半 loopback                RAGFlow（直连）
  ├─ GET /api/workbench-knowledge/datasets ──> GET /api/v1/datasets ──────> 知识库列表
  │    （下拉选择，映射为 {id,name}）            （Bearer key，30s 超时）
  └─ POST /api/workbench-knowledge/ask ──────> POST /api/v1/sessions/ask ─> SSE 流式回答
       {question, datasetIds}                   {question, dataset_ids}
       （SSE 逐帧透传，客户端边收边渲染）          （120s 超时 + 断开联动中止）
```

- **流式链路**：`dsh-client-connection` 的 loopback 桥逐块透传 response body，
  宿主半把 RAGFlow 的 SSE 响应体原样作为 loopback Response 返回；客户端
  `response.body.getReader()` 增量解析 `data:` 帧（`answer` 为增量文本、
  `reference.chunks` 为参考文档、`data: true` 结束、`code!==0` 报错）。
- **面板**：知识库下拉 + 问答消息列表（问题气泡、流式回答、参考文档及相似度）
  + 输入行（Enter 提问，输入法组词中不误触发）。原生会话仍在左侧。

## 配置（直连参数）

`build/dsh-desktop.patch.yml` 的 `dsh-workbench-knowledge` 条目：

```yaml
config:
  baseUrl: http://192.168.8.88:9380   # 内网 RAGFlow；服务迁移时改这里
  apiKey: ragflow-…                    # 飞书文档给定的服务 key
```

**直连取舍**（用户决策）：key 随安装包分发、可被提取；公网用户
（ai.touchit.com.cn）不可达内网 RAGFlow。若后续需要公网访问或按用户控权，
迁移路径是 agent_platform 中转（平台已配 `ragflow_*`，加代理端点即可，宿主半
改走 `nongkeEnterprise` 同一交接模式）。

## 包与登记

- `packages/dsh-workbench-knowledge/`：`index.js` 宿主半（2 条 loopback 路由，
  包络约定与 `dsh-workbench-internal` 一致：业务结果 HTTP 200 `{ok,…}`、
  畸形请求 400）、`client.js` 客户端半（`desktopWorkbenches.register`，
  `layout: { businessSide: 'right', businessWidth: 0.38 }`）。
- 登记：根 `package.json` `file:packages/dsh-workbench-knowledge` +
  `build/dsh-desktop.patch.yml` insert（**置于 dsh-workbench-internal 之前**）。
- 测试：`test/workbench-knowledge-routes.test.ts`（注册契约、config 校验、
  包络映射、SSE 透传、错误边界；RAGFlow 上游用 `vi.stubGlobal` 桩）。

## 顺序说明（「排在内部系统上面」）

- 全新安装：内置工作台首次引入顺序跟随插件加载顺序，patch 中已把 knowledge
  置于 internal 之前；实际显示顺序以内网实测为准。
- **已部署用户**：容器 `reconcileLocalProviders` 把新工作台 append 到 `pinned`
  尾部，默认排在「内部系统」之后；在「工作台管理」界面把它拖到顶部一次即可
  （容器已支持 reorder，未为此改动容器通用逻辑）。

## 已知限制

- 每次问答独立（不传 RAGFlow session id），无多轮上下文；后续如需多轮，
  客户端保存 `session_id` 并在 ask 请求带上即可。
- 2026-10-12 本机不在内网，RAGFlow（192.168.8.88:9380）不可达，端到端冒烟
  未做；路由契约由单测覆盖（SSE 帧透传有断言）。内网环境自测路径：
  `npm run dev` → 登录 → 工作台切换器选「知识库问答」→ 下拉选库 → 提问。
