# 启动登录与用户信息展示（agent_platform 账号）设计

- 日期：2026-09-23
- 状态：已确认（用户已通过）
- 涉及仓库：`dsh-desktop`（Electron 宿主）、`agent_platform`（FastAPI，http://localhost:3002）

## 背景与目标

农科小智智能体（dsh-desktop）启动时通过 agent_platform 的用户接口登录；登录后可在桌面端看到当前用户信息。

已确认的决策：

| 决策点 | 结论 |
| --- | --- |
| 登录交互 | 桌面自建登录窗（门禁页），不走 OAuth、不内嵌平台 web 登录页 |
| 登录持久化 | 记住登录：session cookie 加密落盘，启动时静默恢复 |
| 门禁强度 | 硬门禁：未登录不能进主界面；平台不可达时给"重试/退出"，不白屏 |
| 信息展示 | 登录成功页显示用户信息卡 + 主界面常驻角标 |
| 角标实现 | preload 注入 DOM（接缝模式），不用 WebContentsView、不加 client-ui slot |
| 服务器地址配置 | 嵌在登录门禁页内（收起的"服务器设置"区），持久化；不做独立设置页 |

## 平台侧现状（调研结论）

- 登录：`POST /api/auth/login`，JSON `{username, password}`；成功写 Starlette session cookie 并返回 `{code:0, success:true, data:{id, username, role}}`；失败 `{code:401/403/400, success:false, message}`（401 用户名或密码错误、403 账户禁用）。
- 会话：cookie 签名校验 + `Max-Age` 默认 **14 天**（`app/main.py` 只传了 `secret_key`）。记住登录的天然上限即 14 天，到期自动回落登录页。
- 服务端**未配 CORS** → 登录请求必须放在 Electron 主进程（Node fetch），不能从 renderer 直连。
- 现无"我是谁"接口，需新增（见下）。
- User 模型字段：`username`、`nickname`（中文姓名）、`email`、`role`、`tenant_id`。

## 总体流程

```
应用启动
 ├─ Harness 子进程照常并行启动（登录不阻塞后端启动）
 └─ 主进程 enterprise 模块尝试恢复会话
     ├─ 有有效 cookie（GET /api/auth/me 200）→ 直接进主界面（带角标）
     ├─ 无 cookie / 会话过期 / me 401 → 主窗口加载登录门禁页
     │    ├─ 账号密码 → POST /api/auth/login 成功 → 用户信息卡 → 点"进入" → 主界面
     │    └─ 平台不可达 → 错误提示 + [重试] [退出]
     └─ 角标菜单"退出登录" → 清会话 → 回登录门禁页
```

## agent_platform 改动

新增 `GET /api/auth/me`（`routers/api.py`）：

- 读 `request.session["user_id"]`，查 User（join Tenant 取 `tenant_name`），返回 `_success({id, username, nickname, email, role, tenant_id, tenant_name})`。
- 未登录 / 用户不存在或禁用 → 401（HTTP 状态码，供桌面端判定会话失效）。
- 登录接口与会话机制不动。

## dsh-desktop 改动

### 主进程：`src/main/enterprise/`（新模块，AGENTS.md 已预留该目录职责）

- `auth.ts`：
  - 平台地址：内置默认 `http://localhost:3002`，登录页"服务器设置"可修改并持久化（与 cookie 同一存储，地址为非敏感明文）。
  - `login(username, password)`：主进程 fetch `POST /api/auth/login`；成功后从 `set-cookie` 提取 session cookie，缓存用户信息并持久化。
  - `restore()`：读落盘 cookie → `GET /api/auth/me` 验证；200 则恢复用户信息，401/网络失败则视为未登录。
  - `logout()`：尽力 `POST /api/auth/logout`，无论成败都清除本地会话。
  - 持久化：userData 下 JSON 文件，cookie 值用 Electron `safeStorage` 加密；**密码永不落盘**。
  - fetch 统一 10s 超时；错误码映射：401→"用户名或密码错误"、403→"账户已禁用"、网络失败→"无法连接平台"。
- IPC（校验发送窗口 + 主 frame，沿用现有可信来源校验）：`enterprise:login`、`enterprise:get-user`、`enterprise:logout`、`enterprise:get-server-url`、`enterprise:set-server-url`（校验 URL 格式；改地址会使既有会话失效，清除会话回到登录态）。
- 门禁接线（`index.ts`）：在 `openHarness` 前加统一 choke point——未认证则先加载登录页并暂存待打开的 harness URL，登录成功后继续原 openHarness 流程；**safe-mode 恢复路径不设门禁**（平台故障不能阻塞排障）。

### 登录门禁页：`build/enterprise-login.html`

- 复用主窗口 + 共享 preload，新暴露 `dshEnterprise` 桥（照 `dshWebImport` 模式：`contextBridge.exposeInMainWorld` + 对应 `ipcMain.handle`）。
- 三态：表单（用户名/密码/登录）→ 错误（内联提示；平台不可达给重试+退出，并附"修改服务器地址"快捷入口）→ 成功（用户信息卡 + "进入"按钮）。
- 服务器设置：表单下方收起的"服务器设置"区，展开后显示当前平台地址输入框 + 保存；保存即持久化并用于后续请求。登录后修改地址需先退出登录回到本页。

### 主界面常驻角标：preload 新模块 `enterprise-chip.ts`

- 参考 `windows-titlebar.ts` / 插件错误浮层的接缝模式：preload 在 harness 页面注入固定右上角小角标——首字母圆头像 + 昵称（fallback 用户名）。
- 避让 Windows 标题栏：复用 `--dsh-titlebar-safe-inset-*` 变量；macOS 顶部留出安全高度。
- 点击弹出卡片：完整信息（用户名/昵称/角色/邮箱/租户）+ 退出登录。
- 数据：页面加载后 `invoke('enterprise:get-user')`；跟随明暗主题。
- 退出登录 → 清角标 → 主进程导航回登录门禁页。

## 错误处理

- 登录失败：表单内联错误（区分账号密码错误/禁用/网络不可达）。
- 平台不可达（启动恢复与登录时）：明确提示当前平台地址，提供重试、修改服务器地址与退出。
- 会话中途过期：角标数据拉取失败（401）即回登录页。
- 所有异步路径有失败出口，错误不吞、不伪装成功。

## 测试

- dsh-desktop（vitest）：`enterprise/auth` 单测（mock fetch）：cookie 提取、safeStorage 持久化往返、超时、错误码映射、restore 三分支、服务器地址读写与非法 URL 拒绝。
- agent_platform：`/auth/me` 已登录 / 未登录 / 禁用用户三例。
- 手动（dev 模式）：首次登录、重启免登录、登出回登录页、平台关闭时启动（重试/退出）。

- harness Web UI 内部与 agent_platform 的业务联动（本期登录仅用于身份展示）
- 独立桌面设置页（服务器地址本期嵌在登录页内；将来设置项变多再抽独立页）
- 多平台账号管理
