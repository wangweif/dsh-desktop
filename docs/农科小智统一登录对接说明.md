# 农科小智统一登录对接说明（桌面端）

> 2026-10-12 落地。桌面客户端（农科小智智能体）的登录从「agent_platform 用户名/密码」
> 迁移为「农科小智统一账号」（院内 OAuth2/OIDC IdP）。本文记录方案选型、流程与
> 错误处理，供后续维护参考。

## 方案选型：借道 agent_platform SSO

农科小智 IdP 的接口规范见飞书 wiki《农科小智 OAuth2/OIDC 接口文档》
（[接口文档](https://bjzntdwljsyxgs.feishu.cn/wiki/I8Icw8AP9ibnjnkMIDccMqMbnpd)，
公网地址 `https://llm.bjzntd.com`，内网示例 `http://192.168.8.250:8082`，
仅支持授权码流程）。桌面端接入有两条路线：

| 路线 | 说明 | 结论 |
| --- | --- | --- |
| **借道 agent_platform SSO（已采用）** | 桌面端内嵌授权窗口打开 `{serverUrl}/oauth/login`，复用 agent_platform 已落地的 OAuth2 授权码流程；壳只识别登录成功落地页并提取会话 cookie | 改动集中、凭据链路零改动、无需在 IdP 注册新 client |
| 桌面直连 IdP | 桌面自己作为 OAuth client（client_secret 打包进应用，redirect_uri 需固定） | agent_platform `/api/*` 不认 IdP Bearer token，需跨仓库改造平台后端 + nongkeEnterprise 交接/刷新逻辑全部重做，收益不成比例 |

关键事实：agent_platform 的 `/oauth/callback` 成功后写入的会话 cookie 就是
`agent_platform_session`——与桌面端密码登录时代提取的**同名同源**。因此登录方式
换成 SSO 后，cookie 落盘（safeStorage）、`session-handoff` 交接文件、
`nongkeEnterprise` 复用服务、升级源跟随 serverUrl 等**全部原样工作**。

## 登录流程

### 启动门禁

普通 Profile 在组合维护及后端启动前必须完成认证。已有会话调用
`/api/auth/me` 验证有效后可直接进入；过期、被拒绝或平台不可达时显示登录页。
平台不可达时保留磁盘加密凭据供下次重试，但本次不允许用缓存用户信息进入。
`enterprise:enter` 在主进程再次检查认证状态，不能仅靠页面隐藏按钮限制进入。

认证成功还须等待 `<DSH_HOME>/enterprise/agent-platform-session.json` 的
会话交接写入完成，知识库与平台智能体插件随后从该文件读取同一登录态。
这一改动属于 Profile 组合和后端启动之前的宿主门禁，不改变插件解析 anchor
或客户端加载协议。Safe Mode 保留现有独立恢复入口。
取消授权、验证失败或交接失败均不启动普通 Profile，不删除用户 Profile 数据。

```
登录页(enterprise-login.html)      主进程                       agent_platform          农科小智 IdP
  │ 点击「农科小智统一账号登录」    │                                │                      │
  ├─ enterprise:login-sso ────────>│ openEnterpriseSsoLogin()      │                      │
  │                                ├─ 模态窗口 load /oauth/login ─>│ 302 授权页 ─────────>│
  │                                │                               │ <─ 登录 + 同意授权 ──┤
  │                                │                               │<─ 302 callback?code ─┤
  │                                │  did-navigate 命中落地页       │ (写 agent_platform_  │
  │                                │  (/portal|/scenarios|/)        │  session cookie)     │
  │                                ├─ session.cookies 提取 cookie   │                      │
  │                                ├─ auth.loginWithSessionCookie() │                      │
  │                                │  └─ GET /api/auth/me 验证 ───>│                      │
  │                                ├─ #persist（safeStorage 落盘 + onChange → 交接文件）    │
  │  <─ {ok:true, user} ───────────┤ 窗口自动关闭                   │                      │
  │  自动进入客户端               │                               │                      │
```

用户在授权窗口看到的是农科小智 IdP 的登录/授权页——**农科小智账号密码只在 IdP
页面输入，桌面端不接触**。IdP 地址、client_id/secret 全部由 agent_platform 侧
配置（`app/config.py` 的 `oauth_*`）；桌面端只校验已知认证中心的导航来源。

平台会话验证及交接完成后，授权窗口自动关闭并聚焦客户端主窗口；主进程直接
解除登录门禁，登录页无需再点击「进入」。取消、授权失败或会话未就绪不会进入客户端。

### 部署前置条件与实际状态

业务平台地址（默认 `https://ai.touchit.com.cn/agent`）和认证中心地址承担不同职责。
不能把业务平台地址替换为认证中心首页：知识库和智能体的 `/api/*` 仍由业务平台
提供，其会话 cookie 由平台完成 OAuth 回调后建立。

管理员需在认证中心登记业务平台的 OAuth 客户端及实际部署的 `/oauth/callback`，
在平台服务端配置 `oauth_idp_base_url=https://llm.bjzntd.com`、对应 client_id、
client_secret 和 redirect_uri；密钥不放进桌面安装包。接口文档中的客户端参数是
示例，不能据此声称真实账号可以登录。

2026-10-13 已部署公网专用配置（`OAUTH_PUBLIC_*`），客户端 `dsh_desktop` 的
回调登记为 `https://ai.touchit.com.cn/agent/oauth/callback`。线上实测
`/agent/oauth/login` 已 302 到 `https://llm.bjzntd.com/oauth/authorize`，
认证中心接受该客户端与回调，并继续跳转到 `/auth` 登录页。
密钥仅存业务平台服务端 `.env`。尚未使用真实用户完成授权和知识库问答验收。
本机 Electron 的系统代理会导致该链路连接失败；临时隔离会话直连时已实际到达
认证中心 `/auth` 页面，正式客户端及系统代理配置未因此改动。

## 代码索引

| 文件 | 职责 |
| --- | --- |
| `src/main/enterprise/sso.ts` | 授权窗口编排：`openEnterpriseSsoLogin`（模态窗口、导航白名单、落地页识别、cookie 提取）+ `isPostLoginLandingUrl`（BASE_PATH 兼容的落地页判定） |
| `src/main/enterprise/sso-policy.ts` | 业务平台与农科小智认证中心的导航白名单；平台本地登录页的失败分类 |
| `src/main/enterprise/auth.ts` | `loginWithSessionCookie`：以捕获的 cookie 建立登录态（`/api/auth/me` 验证 + 落盘）；原 `login(username, password)` 已移除 |
| `src/main/enterprise/ipc.ts` | `enterprise:login-sso` 通道（主窗口信任守卫） |
| `build/enterprise-login.html` | 登录页：SSO 单按钮 + 服务器设置（保留），密码表单已移除 |
| `test/enterprise-sso.test.ts` 等 | 落地页判定、`loginWithSessionCookie`、IPC 各自的单测 |

安全要点：授权窗口 `sandbox` + `contextIsolation`，禁 `nodeIntegration`；禁新窗口
与 webview；页面导航及 HTTP 重定向只允许业务平台、`https://llm.bjzntd.com`
和内网示例 `http://192.168.8.250:8082`，其他来源拦截并返回错误。
权限请求沿用 `canGrantWindowPermission`。

## 错误处理

| 场景 | 行为 |
| --- | --- |
| 用户关闭授权窗口 | 返回 `cancelled`，登录页静默恢复按钮 |
| 平台不可达（`did-fail-load`/loadURL 失败） | 返回 `unreachable`，登录页显示「重试 / 修改服务器地址 / 退出」 |
| 平台未启用 SSO，跳到 `/login` | 关闭授权窗口，明确提示管理员配置 OAuth 客户端 |
| IdP 拒绝授权 / 账号被平台拒绝，跳到 `/login?oauth_error=…` | 关闭授权窗口，返回统一账号授权失败，用户可在桌面登录页重新授权 |
| 会话 cookie 被平台拒绝（`/api/auth/me` 401） | 窗口保留，登录页不误报成功，用户可关闭后重新授权 |

## 管理员账号

agent_platform 侧 SSO 仅放行租户用户（`tenant_user`/`tenant_admin`），且
`super_admin` 走 SSO 一律拒绝。桌面统一登录不再回退到平台本地密码页；
平台管理员仍可通过业务平台网页使用本地管理员登录。

## 与 nongkeEnterprise 复用服务的关系

不变。登录成功后 `#persist` 触发 `onChange` → `writeEnterpriseSessionHandoff`
写 `<DSH_HOME>/enterprise/agent-platform-session.json`，dsh 插件
`dsh-enterprise-agents` 的 `nongkeEnterprise` 服务（apiGet/apiPost）照旧现读交接
文件调用平台接口。设计详见《企业认证复用服务nongkeEnterprise》。

## 已知取舍

- **access_token 不落桌面端**：SSO 的 access_token/id_token 由 agent_platform 服务端
  用完即弃，桌面端只持有平台会话 cookie（与密码登录时代一致）。桌面端无需实现
  token 刷新/轮换。
- **cookie 过期需重新走 SSO**：无静默续期。`restore()` 失败后登录门禁弹登录页，
  用户重点一次 SSO 按钮；由于 IdP 有自己的会话，二次授权通常免密。
