# 迁移 DeepSeek 官方桌面版可行性评估

调研日期：2026-10-04
对象：`deepseek-ai/deepseek-harness` monorepo（236k star）中的官方桌面端 `apps/desktop`（npm 包 `@deepseek-ai/dsh-desktop`，当前 0.2.1-alpha.1）
背景：农科小智现基于第三方壳 `dataelement/dsh-desktop`（BISHENG），企业定制已随 2026-10-04 合并升级到官方内核 0.2.0-rc.2 + Office。

## 一、官方桌面版架构（实地读码结论）

- **三层组合**：Electron 壳（`apps/desktop`，主进程 main.ts 仅 1349 行，较薄）+ 私有 Host 包（`@deepseek-ai/dsh-desktop-host`）+ **签名不可变内核 tarball 集**（`desktop-packages.json`，含 dsh 全闭包，profile 相对目录安装）
- **Web UI 完全插件化**：`packages/client` 下 80+ 个 `ui-*` 插件（ui-chat、ui-sidebar、ui-agent-preset、ui-brand-official……），通过 `ui-slots` 注册表组合（single/list/keyed/chain 四种 slot + store 席位 + 类型检查）。插件是运行时 fetch bundle，经 platform module 表解析 externals——**第三方 UI 插件不需要 fork 客户端**
- **Office 引擎官方内置**：`desktop-host/src/office-engine.ts`（Word/Excel/PPT，与 dataelement 壳接的是同一套，源头都在官方）
- **品牌替换是官方支持的正规路径**：`ui-brand-official` README 明言"使用其他品牌的部署应提供替代品牌包""自有身份的部署不组合本包，而是组合另一个占据侧栏 slot 的包"——**slot 占位制，无品牌配置面，不 fork 就能换品牌**
- **强制更新体系**（`mandatory-update-policy.ts` + 更新策略服务端下发）走 download.deepseek.com，签名校验——**定制版的更新链路是最大风险点**（官方更新可能覆盖/拒绝定制构建，需实验确认能否换源或禁用）
- 平台支持：Mac 仅 arm64 + Win x64（与新闻一致）

## 二、农科小智企业功能 → 官方版承载路径

| 功能 | 现实现（dataelement 壳） | 官方版路径 | 可行性 |
|---|---|---|---|
| 品牌改名 | productName + 改壳内字符串 | 替代品牌包占 sidebar slot | ✅ 低成本，官方路径 |
| 平台智能体页（agents.html + 侧边栏入口 + IPC） | 壳内 HTML 页 + preload 桥 | 写一个 dsh 客户端 slots 插件（侧边栏条目 + 自定义视图） | ✅ 可行，需按 slot 体系重写 |
| 平台 preset 下载/安装/卸载 | 主进程 preset-transfer 模块 | preset 在官方是一等概念（ui-agent-preset + Creator/Plugin Manager 内置 pnpm） | ✅ 概念对齐，对接层重写 |
| 本地创作上传平台 | persona-extract + auth.apiPost | 同上插件内实现（HTTP 直连 agent_platform） | ✅ 纯增量 |
| 企业登录门禁（启动强制登录） | enterprise-login.html + openHarness 门禁 | 两条路：a) 扩展官方 Platform 账号体系（有账号凭证 IPC/失效处理，概念接近）；b) fork 壳加门禁 | ⚠️ 需设计，官方账号绑定 DeepSeek 平台，接 agent_platform 要绕开 |
| 自动更新（农科小智自己的发版链路） | 自有 GitHub release + 灰度 | 官方强制更新策略需替换/禁用 | ⚠️ 最大风险点，未验证 |

## 三、工作量估算（迁移 vs 留守）

**迁移到官方桌面版：约 3–5 周**
- 替代品牌包：1–2 天
- 平台智能体 slots 插件（列表/下载/上传/侧边栏）：1–2 周（含学习 slot/fetch-bundle 体系）
- 企业登录门禁（主进程改造 + welcome 流程）：约 1 周
- 更新链路适配/禁用 + 双平台出包验证：2–3 天（含实验）
- 持续成本：官方 API 处于 preview 快速变动期，追上游有长期维护负担

**留守 dataelement 壳：0（已完成）**
- 昨日合并后内核已与官方桌面版同版本（0.2.0-rc.2），Office 同源
- 代价：跟随的是 BISHENG 的壳维护节奏（该壳自述 early preview，若官方版成熟后 BISHENG 弃维护，仍有迁移一天）

## 四、建议：插件化铺路的混合策略

1. **短期（现在）**：留守 dataelement 壳。内核已对齐，定制全在，零边际成本。
2. **中期（1–2 个月内）**：把「平台智能体页」从壳内 HTML 重构为**标准 dsh 客户端插件**（slots 体系）。关键洞察：**两边的 Web UI 是同一套插件体系**（dataelement 壳同样组合 `@deepseek-ai/dsh-client-ui-*`），插件化后的代码在两个壳上都能跑——这是一笔无论将来迁不迁移都保值的投资。
3. **迁移触发条件**（满足其一再启动官方版迁移）：
   - 官方桌面版出正式版（非 rc/preview）且更新机制支持自定义源
   - dataelement 壳停止跟进官方内核
   - 出现只有官方版才有的硬需求（目前没有：Office、preset、插件市场两边都有）

## 五、验证缺口

以下结论来自读码 + 文档，未实验验证，启动迁移前需 PoC：
- 官方桌面强制更新能否对非官方签名的定制构建放行/禁用
- 非 `official` build profile 下组合自有品牌包 + 自有插件的完整构建流程
- agent_platform 账号体系与官方 Platform 账号体系的共存方式
