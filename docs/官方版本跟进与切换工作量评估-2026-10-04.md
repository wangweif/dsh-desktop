## 二、官方是否已有编写 Word/Excel 的插件？——**有**

- **形态**：不是插件市场里的可选插件，而是**安装包内置能力**。`packages/dsh-desktop-office` 在安装时组合上游 `@deepseek-ai/dsh-skill-office` 技能包 + workspace-dependencies 工具，普通 Profile 自动加载（Safe Mode 不加载）。
- **覆盖**：Word（python-docx 1.2.0）、Excel（openpyxl 3.1.5 + XlsxWriter 3.2.9）、PPT（python-pptx 1.0.2），外加 pandas 3.0.1 / numpy 做数据处理。包内验收标准就是"实际调 Python 创建并重新读取 DOCX/PPTX/XLSX"，还约束 ZIP 条目必须正斜杠（防 Windows PowerShell Compress-Archive 反斜杠坑）。
- **转换**：带 LibreOffice Kit（以 Electron Node 模式运行）做格式转换/校验。
- **状态**：⚠️ 只在官方 **main** 上（2026-10-02 提交），**尚未进正式发布 tag**——最新 tag v0.9.2 是 2026-09-23。预计随下一版本正式发布。

结论：不需要自己开发 Word/Excel 插件，切到官方新版本即得；如果现在就要，得跟 main（未发版，风险自担）。

### 真正的工作量在语义适配（比文本冲突大）

1. **dsh 0.1.5 → 0.2.0 patch 全换代**：本地 patches/ 目录 30 个 patch 全部对应旧版本名，需对照上游新 patch 逐一重放本地定制（若有）。
2. **ASAR 打包重构适配**：品牌资源安装脚本（install-brand-assets.mjs 文本合并已通过，但要在 ASAR 布局下实测）、Windows 签名脚本、after-pack 链路。
3. **企业模块回归**：dsh 0.2.0 的 session-controller / api-remotes 等 patch 变化可能影响企业 IPC 契约，需跑 `test/enterprise-*` 全套 + 登录门禁/平台智能体上传下载实测。
4. **windows-menu 删除迁移**：侧边栏用户角标挂载点要找上游新家。
5. **发布链路双平台实测**：上游打包方式大改（去捆绑 Node、ASAR），Windows/mac 都要出包验证；Office runtime 会让安装包增重 ~200 MiB，农科小智的发版/分发链路要评估。
