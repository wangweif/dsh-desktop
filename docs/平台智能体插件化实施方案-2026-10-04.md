## 0. 已验证的关键机制（实施前提，全部来自本仓库现状）

1. **双半侧插件先例**：`packages/dsh-desktop-client-ui/`——一个包双导出（`.` host 半 / `./client` client 半），package.json `dsh.client.inject` 声明 client 可 require 的模块，`platform: "web"`。client 半是 `window.__ModuleLoader__.load({id, factory})` 手写纯 `React.createElement`（packages/dsh-desktop-client-ui/client.js:1，200 行先例），**无构建步骤**。
2. **整页面板先例**：官方 `@deepseek-ai/dsh-client-ui-plugin-manager/lib/client.js:3712-3775`——`ctx.slots.inject('main', ...)` 内 `ctx.slots.register({name:'main', key: PANEL_ID, locale: NS, inject:()=>face}, Page)`；侧边栏入口 `ctx.slots.inject('sidebar.panellist', () => ctx.slots.register({name:'sidebar.panellist', id: PANEL_ID, order, label:()=>t('panel')}, PanelIcon))`；打开面板 `ctx.layout.selectPanel(PANEL_ID)`。
3. **loopback 路由先例**：`packages/dsh-desktop-preset-transfer/index.js:293-343`——host 半 `ctx.connection.fetch.register({path, methods, fetch})`，client 侧同源 `fetch('/api/...')`（官方 agent-preset UI 即如此，node_modules/@deepseek-ai/dsh-client-ui-agent-preset/lib/client.js:919）。路由由 carrier 施加浏览器会话信任策略，无需自带鉴权。
4. **preset 根目录自取**：preset-transfer 用 `ctx.get('agentPresets').roots.find(r => r.trust === 'user').path`（回退 `process.env.DSH_HOME + '/.agent-presets'`）——插件不需要壳传配置。
5. **插件进 dsh 依赖闭包**：`desktop-plugin-closure.test.ts` 要求 patch.yml 里每个 insert 的包必须被注入 `@deepseek-ai/dsh` 的 dependencies——做法是改 `patches/@deepseek-ai+dsh+0.2.0-rc.2.patch`（现文件 15-40 行已注入全部桌面插件 + react-dom）。**漏这一步 = 整个插件树启动失败**。
6. **登录门禁时序**：`openHarness()` 先 `await ensureEnterpriseAuthenticated()`（src/main/index.ts:1058、1220）——**harness UI 可见时用户必已登录**，插件的会话文件必已写入（见 §2）。DSH_HOME 由 HarnessRuntime 传给子进程（harness-runtime.ts:322）。
7. **现有消费方**：`window.dshEnterprise` 的 agents 方法只有 build/agents.html 用；enterprise-login.html 只用 login 族方法（保留）。`src/shared/persona-extract.ts` 只有 agents.ts 与 test/persona-extract.test.ts 用。

## 1. 包结构

**决策：单包 `packages/dsh-enterprise-agents/` 双导出（同 dsh-desktop-client-ui 先例），不拆两包。** 理由：host/client 两半共享类型与常量、同仓同版本、上游 workbenches/client-ui 全是单包双导出先例；拆两包徒增 closure patch 行数与版本漂移面。

**client 半手写纯 `React.createElement`，不引入构建。** JSX/htm 都不可行：htm 不在 client require 基线（基线仅 react/react-dom/cordis/dsh-client-store/ui-slots/ui-primitives/ui-dockkit 等，htm 非 dsh 包无法进 client 模块图）；引入 tsdown/esbuild 构建则违背本仓 packages/ 全部手写零构建的惯例。写法上用一个局部 `h = React.createElement` 别名 + 每卡片一个小组件函数，规模可控（估计 600-800 行，agents.html 现 648 行同量级）。

## 2. API 面（host 半）

### 2.1 路由清单（IPC → loopback 一一映射）

| 现有 IPC 通道 | 新路由 | Method | Body | 返回（HTTP 200，原样业务包络） |
|---|---|---|---|---|
| `enterprise:agents:list` | `/api/enterprise-agents/platform` | GET | – | `AgentListResult` |
| `enterprise:agents:installed` | `/api/enterprise-agents/installed` | GET | – | `{ok:true, agents}` |
| `enterprise:agent-download` | `/api/enterprise-agents/download` | POST | `{agentId}` | `AgentInstallResult` |
| `enterprise:agent-uninstall` | `/api/enterprise-agents/uninstall` | POST | `{presetId}` | `AgentUninstallResult` |
| `enterprise:local-presets` | `/api/enterprise-agents/local-presets` | GET | – | `LocalPresetListResult` |
| `enterprise:agent-upload` | `/api/enterprise-agents/upload` | POST | `{presetId}` | `AgentUploadResult` |
| `enterprise:open-agents` / `enterprise:close-agents` | **删除** | – | – | 面板切换改 `ctx.layout.selectPanel(PANEL_ID)`（client 侧，无路由） |

**错误包络映射**：业务结果原样 200 返回（`{ok:false, code, message}` 里 message 已是面向用户的中文）；仅请求本身畸形（非 JSON、缺字段、字段非 string）回 `400 {ok:false, code:'invalid', message:'请求参数无效'}`。这与 preset-transfer 的 `Response.json` 模式一致，且 client 判定只看 `ok` 字段，测试断言可直接复用现有 shape。

### 2.2 登录态协调：会话交接文件（本方案的核心机制）

登录门禁与 safeStorage 加密都留在主进程；host 插件（运行在 harness 子进程）通过**会话交接文件**拿到 agent_platform 会话：

- **路径**：`<dshHome>/enterprise/agent-platform-session.json`（即 `$DSH_HOME/enterprise/agent-platform-session.json`），内容 `{ serverUrl, sessionCookie }`，`mode 0o600`，原子写（tmp+rename，Windows 兜底同 auth.ts 的 atomicWriteJson）。
- **写入点（主进程）**：给 `EnterpriseAuth` 增加可选 `onChange?: (snapshot: { serverUrl: string; sessionCookie?: string }) => void` 回调，在现有 `#persist()` 成功后触发——`#persist` 已覆盖全部状态变化点（login 成功、logout、setServerUrl 作废、restore 刷新），单一挂点不用散弹修改。index.ts 里把 onChange 接到 `writeEnterpriseSessionHandoff(dshHome, ...)`：有 cookie 写文件，无 cookie 删文件（logout/serverUrl 变更）。
- **读取点（插件）**：`lib/session-file.js` 提供惰性读——每次路由请求用到 auth 时现读文件（读盘 <1ms，简单且无缓存失效问题）；另对 `$DSH_HOME/enterprise/` 目录 `fs.watch`，文件出现/变化 → 更新内存 + 触发一次 `syncAgents`（对齐现在主进程 restore 后、onEnter 后的同步行为），文件删除 → 清内存会话。watch 目录用目录而非文件（Windows 上被替换文件的 watch 会断）。
- **时序安全**：`openHarness` 在门禁之后（已验证 §0.6），所以面板可见时会话文件必在；harness 先于登录启动的场景（restore 未完成）文件尚缺，插件按未登录处理，watch 到文件出现再同步——与现状「restore 后 sync」语义一致。

### 2.3 host 半 index.js 骨架

```js
import { EnterpriseAgentStore } from './lib/store.js'
import { createSessionFileAuth } from './lib/session-file.js'

export const name = 'dsh-enterprise-agents'
export const inject = ['connection', 'agentPresets']

const INVALID = Response.json(
  { ok: false, code: 'invalid', message: '请求参数无效' },
  { status: 400, headers: { 'cache-control': 'no-store' } }
)

export function apply(ctx) {
  const connection = Reflect.get(ctx, 'connection')
  const presets = ctx.get('agentPresets')
  const userRoot = presets?.roots?.find((root) => root.trust === 'user')?.path
  const presetRoot = userRoot
    ?? (() => {
      const home = process.env.DSH_HOME
      if (!home) throw new Error('DSSH_HOME is not configured for enterprise agents')
      return `${home}/.agent-presets`
    })()
  const auth = createSessionFileAuth()          // 惰性读 + 目录 watch
  const store = new EnterpriseAgentStore({
    presetRoot,
    log: (line) => console.warn(line)           // 落 harness ring → harness.log
  })

  const json = (data) => Response.json(data, { headers: { 'cache-control': 'no-store' } })
  const post = (handler) => async (request) => {
    let body
    try { body = await request.json() } catch { return INVALID }
    if (typeof body !== 'object' || body === null) return INVALID
    return json(await handler(body))
  }

  connection.fetch.register({
    path: '/api/enterprise-agents/platform',
    methods: ['GET'],
    fetch: async () => json(await store.listPlatformAgents(auth.get()))
  })
  connection.fetch.register({
    path: '/api/enterprise-agents/installed',
    methods: ['GET'],
    fetch: async () => json({ ok: true, agents: await store.listInstalledAgents() })
  })
  connection.fetch.register({
    path: '/api/enterprise-agents/download',
    methods: ['POST'],
    fetch: post((body) => store.installAgent(auth.get(), String(body.agentId ?? '')))
  })
  connection.fetch.register({
    path: '/api/enterprise-agents/uninstall',
    methods: ['POST'],
    fetch: post((body) => store.uninstallAgent(String(body.presetId ?? '')))
  })
  connection.fetch.register({
    path: '/api/enterprise-agents/local-presets',
    methods: ['GET'],
    fetch: async () => json(await store.listLocalPresets())
  })
  connection.fetch.register({
    path: '/api/enterprise-agents/upload',
    methods: ['POST'],
    fetch: post((body) => store.uploadAgent(auth.get(), String(body.presetId ?? '')))
  })

  // 会话文件出现/变化（登录、重新登录）→ 后台对齐平台分配；删除（登出）→ 只清会话。
  auth.onSessionChange((session) => {
    if (!session) return
    void store.syncAgents(session)
      .then((outcome) => { if (!outcome.ok || outcome.failed > 0) console.warn('[enterprise] agent sync incomplete') })
      .catch((error) => console.warn(`[enterprise] agent sync failed: ${error}`))
  })
  // 若启动时文件已存在（门禁先于面板），立即同步一次
  if (auth.get()) auth.onSessionChange.current?.(auth.get())   // 实现为：apply 尾部直接跑一次 sync
}
```

（骨架最后一行仅示意「启动即同步」；实现时写成显式的 `runSync(auth.get())` 调用，避免闭包技巧。）

`session-file.js` 的 `auth.get()` 返回一个实现 `apiGet/apiPost/getServerUrl` 的轻对象——**把 auth.ts 中 `apiGet/apiPost` 的包络解析逻辑（超时、401/403→unauthorized、200+success:false→error）复制为包内独立函数**，cookie 来源从内存字段换成交接文件。这样 store.js 完全不用改调用面。

### 3.1 移植而非改写

`src/main/enterprise/agents.ts` 的 `EnterpriseAgentStore` 及纯函数**逐行移植为包内 JS**（`lib/store.js` + `lib/composition.js` + `lib/persona-extract.js`）：

### 3.3 safeStorage 凭证：主进程存储 + 文件转交（不降级到自造加密）

- 加密存储（safeStorageCodec）原样留在主进程 `<userData>/enterprise/session.json`。
- 交接文件是**明文 cookie + 0600**，这是有意的取舍：自造 Node crypto 加密（密钥也得落盘）只是伪装安全。仓库内先例：`dsh-credentials-local` 对磁盘凭证正是 0600 强制姿态（node_modules/@deepseek-ai/dsh-credentials-local/lib/index.js:104 甚至对超权限 mode 直接 throw）。缓解：文件仅在登录会话存在期间落盘、logout/换服务器即删、放 userData 内（用户级目录权限再加一层）。
- 迁移到官方桌面版时的演进路径：会话来源已被抽象成文件，未来可在插件里加登录面板 + `/api/enterprise-agents/session` 路由写同一文件（开放问题 §7）。

## 7. 风险与开放问题

### 风险（按翻车概率排序）

1. **dsh 依赖闭包遗漏**：patch.yml insert 而未改 `patches/@deepseek-ai+dsh+...patch` → harness 启动即 `Cannot find package ...`，**整棵插件树失败**（不只本插件）。对策：第 2 步先跑 `desktop-plugin-closure.test.ts` 再起应用；这是唯一"全盘皆输"点。
2. **client require 面与 `dsh.client.inject` 声明不匹配**：require 了未声明且非基线的模块 → 面板白屏或静默不出现。对策：对照 plugin-manager（layout/locale）与 client-ui（primitives/react 基线）两个先例的声明；devtools console 的 ModuleLoader 报错可定位；第 3 步首验就在侧边栏看图标是否出现。
3. **会话交接文件的生命周期边角**：logout 删除 vs 插件内存缓存（路由继续放行旧 cookie）；`setServerUrl` 作废会话但 serverUrl 变了文件却删了——插件需同时感知（watch 事件里重读全量）。对策：路由侧每次现读文件（不做内存长期缓存），watch 只用于触发 sync；`test/enterprise-agents-routes.test.ts` 覆盖"文件不存在→unauthorized"分支。
4. **`main` slot 面板 API 漂移**：`slots.register({name:'main', key, locale, inject})` 的准确字段以 0.2.0-rc.2 的 plugin-manager 反编译用法为准（§0.2 已核对）；未来升 rc 需复核。children/scope 声明（plugin-manager 有 `children:{...}`）本页不需要（无嵌套 slot 扩展点），少声明不影响渲染。
5. **对等清单遗漏**：React 重写最容易丢"列表失败降级展示已装"、"上传 404 回退重建"这类暗逻辑——后者在 store 移植里原样保留（测试覆盖），前者在对等清单里显式验收（§4.2）。

### 开放问题（不阻塞实施，标注后续迭代）

1. **官方桌面版上的登录**：迁到 DeepSeek 官方桌面后无壳门禁/交接文件写入者。会话来源已抽象为文件 + 可扩展：后续给插件加登录表单面板 + `POST /api/enterprise-agents/session` 写同一文件即可，不动 store。
2. **未登录时面板可见性**：官方环境下未登录则路由 unauthorized，面板显示"登录已过期"横幅即可（农科小智内门禁保证不可见）。
3. **同步失败的用户可见性**：现状 sync 失败只记 harness.log；将来可在面板顶部展示"同步失败"轻提示（数据已有，纯 UI 增强）。
4. **交接文件与多窗口/多 harness 实例**：当前壳单实例单 harness，无并发写问题；官方环境多 profile 时文件在各自 DSH_HOME 下，天然隔离。
